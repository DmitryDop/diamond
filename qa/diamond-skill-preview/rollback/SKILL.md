# Diamond Rollback

Пользователь принимает финальное решение. Проверка или подготовка не разрешает реальный rollback.

## Настройки Diamond

- Project: `Diamond`.
- Production URL: `https://diamond.palkahelp.ru/`.
- SSH alias: `palkahelp`.
- Remote path: `/home/p/palkahelru/diamond_palkahelp_ru/public_html`.
- Transport: `rsync` по SSH; не FTP/FTPS.
- Публикуй только `index.html`, `css/`, `js/`, `assets/`.

Работай из корня Git-репозитория Diamond. Не отправляй весь корень проекта.

## Git и снимок публикации

Покажи ветку, полный HEAD, staged/unstaged изменения и untracked-файлы. Отдельно проверь `git status --short --untracked-files=all -- index.html css js assets` и ignored-файлы в этих путях. Учитывай новые, изменённые и удалённые публикуемые файлы. Эта проверка обязательна и при BOSS OVERRIDE.

Публикуй отдельный снимок конкретного commit внутри `.deploy/`. Зафиксируй полный SHA; проверь наличие всех четырёх разрешённых путей в commit и снимке. Не включай в снимок незакоммиченные файлы. Не переключай рабочую ветку, не выполняй `git reset --hard`, `git clean -fd` и не переписывай историю пользователя.

Dry-run и реальная загрузка используют один и тот же снимок и одинаковые исключения. При изменении снимка или команды повтори dry-run и подтверждение в SAFE-режиме.

## Защита публикации и серверных данных

Никогда не публикуй секреты, SSH-ключи, credentials, `.env`, `.env.*`, `.git/`, `.agents/`, `.claude/`, `.deploy/`, `.github/`, `.gitignore`, `.DS_Store`, `AGENTS.md`, `CLAUDE.md`, `docs/`, `tmp/`, `PLAN.md`, `qa/`, `previews/` и другие служебные файлы. Проверяй секреты и исключения внутри разрешённых каталогов; сам каталог `assets/` не делает секрет публичным. Не следуй символическим ссылкам за пределы снимка. При угрозе публикации секрета остановись.

Не удаляй и не перезаписывай серверные runtime-данные, пользовательские загрузки и приватные файлы. Если их пути совпадают с публикуемыми файлами, исключи их из передачи или остановись для уточнения. Не определяй назначение только по расширению. Не меняй файлы вне configured remote path.

Не используй `--delete`, `--delete-excluded` и другие destructive options автоматически. Для необходимых удалений покажи точный список и причину и получи отдельное явное разрешение. BOSS OVERRIDE не разрешает удаление автоматически. Отсутствие `--delete` защищает от удаления, но не от перезаписи серверных данных.

## rsync по SSH

Используй совместимые с macOS параметры `-rvz`; для dry-run добавляй `n`. Не используй `-a` без отдельной необходимости.

Пример dry-run из корня проекта; `.deploy/staging/` — подготовленный снимок выбранного commit:

```bash
rsync -rvzn -e ssh \
  --exclude='.env' --exclude='.env.*' --exclude='.DS_Store' \
  --exclude='.git/' --exclude='.agents/' --exclude='.claude/' \
  --exclude='.deploy/' --exclude='.github/' --exclude='.gitignore' \
  --exclude='AGENTS.md' --exclude='CLAUDE.md' \
  --exclude='docs/' --exclude='tmp/' --exclude='PLAN.md' \
  --exclude='qa/' --exclude='previews/' \
  .deploy/staging/index.html .deploy/staging/css \
  .deploy/staging/js .deploy/staging/assets \
  palkahelp:/home/p/palkahelru/diamond_palkahelp_ru/public_html/
```

Дополнительные исключения определи при проверке снимка до dry-run. Для реальной загрузки используй ту же команду без `n`. Не передавай `./` и не добавляй завершающий `/` к исходным каталогам: на сервере должны сохраниться каталоги `css`, `js`, `assets`.

## Production metadata Diamond

Используй только `.deploy/production-current` и `.deploy/production-previous` в корне Git-репозитория Diamond. Они относятся исключительно к указанным Production URL и remote path. Не копируй metadata из других проектов.

Формат каждого файла — один полный SHA commit Diamond с завершающим переводом строки. Проверь SHA через `git rev-parse --verify '<sha>^{commit}'`, наличие публикуемых путей в commit и соответствие известной истории production Diamond. Наличие commit в Git не доказывает, что он опубликован.

При повреждённой или противоречивой metadata остановись для уточнения. Если metadata отсутствует, не угадывай production commit по локальному HEAD; используй известную историю публикаций и Git history, а при неоднозначности спроси пользователя.

Обновляй metadata только после успешной загрузки и smoke-check: current — SHA действительно загруженного снимка, previous — проверенный SHA production до операции. Не подменяй их текущим локальным HEAD. Если current уже равен опубликованному SHA, не меняй историю повторно. Если прежняя версия неизвестна, не придумывай previous и сообщи об этом; при существующем previous с неясным происхождением сначала уточни исправление metadata.

Для Git sync добавляй только изменённые metadata-файлы и создавай отдельный commit через `git commit --only -- <изменённые пути metadata>`, не включая чужие staged/uncommitted изменения. Затем выполни `git push`. Ошибка Git sync не отменяет успешно проверенную публикацию: сообщи её и не повторяй загрузку.

## Обязательный smoke-check и ошибки

После реальной загрузки проверь:
- наличие серверного `index.html` и его соответствие опубликованному снимку;
- HTTP status и отдачу страницы `https://diamond.palkahelp.ru/`;
- основные затронутые ресурсы сайта;
- сохранность затронутых серверных данных чтением, без автоматического удаления посторонних файлов.

Проверяй только configured Production URL, не угадывай другие домены. Не объявляй успех без smoke-check. При ошибке остановись, сообщи этап и текст ошибки, не меняй metadata и не исправляй production молча.

## Источник rollback

Источник — конкретный commit Git Diamond. Сначала проверь metadata: current — известная опубликованная версия, previous — кандидат для отката. Проверь SHA, сообщения commit и различия в разрешённых путях; не доверяй metadata вслепую.

При отсутствии metadata используй известную историю публикаций и Git history. Не считай любой предыдущий commit стабильной production-версией. Если target нельзя определить однозначно, остановись и спроси пользователя, включая BOSS OVERRIDE.

## SAFE ROLLBACK — режим по умолчанию

Для запросов «rollback», «откати», «верни прошлую версию», «откати прод», «верни предыдущий деплой»:

1. Проверь Git по общим правилам и покажи dirty публикуемые файлы. Не включай их в rollback-снимок и не перезаписывай локальную рабочую копию: откат публикует только выбранный исторический commit.
2. Определи current production SHA и конкретный target. Покажи target SHA, commit message и различия в публикуемых файлах. Неизвестный current обозначь явно.
3. Подготовь отдельный снимок target. Не переключай ветку пользователя и не используй destructive Git commands.
4. Проверь исключения, секреты и конфликты с серверными данными. Запусти доступные для снимка тесты и lint-проверки; сообщи о недоступных проверках.
5. Выполни только rsync dry-run. При ошибке не переходи к загрузке.
6. Покажи preview: HEAD, current production и target SHA, восстанавливаемые и исключённые файлы, локальные изменения, проверки и dry-run, target, отсутствие автоматического удаления, риски. Отдельно обозначь файлы новой версии, которые останутся на сервере при откате без удаления.
7. Спроси: `Продолжить rollback?` До явного подтверждения production не изменять.
8. После подтверждения загрузи тот же снимок и выполни обязательный smoke-check.

Если для полного отката нужно удалить файлы новой версии, покажи точный список и причину, затем запроси отдельное явное разрешение. Не удаляй runtime-данные и приватные серверные файлы.

## BOSS OVERRIDE

Явные команды «откатывай сразу», «верни прошлую версию немедленно», «rollback now», «катись назад без проверок» разрешают откат без дополнительного подтверждения.

Пропусти обычные quality checks и dry-run только в объёме явной команды; сообщи, что пропущено. Проверка Git и dirty публикуемых файлов, конкретный target SHA, отдельный снимок, защита секретов и серверных данных обязательны. Не выбирай target наугад и не изменяй локальные публикуемые файлы. BOSS OVERRIDE не разрешает автоматическое удаление. Smoke-check обязателен.

## После успешного rollback

Сохрани проверенный current production SHA до отката. После успешной загрузки и smoke-check запиши target SHA в current, а известный production SHA до отката — в previous по общим правилам. Не подставляй локальный HEAD вместо неизвестной production-версии. Синхронизируй только metadata отдельным commit `Record Diamond production rollback <short-commit>` и `git push`.

Сообщи target SHA, восстановленные и нетронутые файлы, отдельно согласованные удаления, smoke-check и HTTP status, пропущенные проверки, предупреждения и прежний/новый production SHA. При успешной загрузке и smoke-check сообщи `ROLLBACK: SUCCESS`; ошибку Git sync укажи отдельно.
