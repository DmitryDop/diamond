# DIAMOND — исправление регрессии «Характера»

## Диагностика

- `git status --short` возвращает `fatal: not a git repository`. Репозитория `.git` в проекте нет. `git diff -- index.html css/styles.css` вне репозитория сравнил HTML с CSS как два файла; это не история изменений и не основание для отката.
- Последняя версия рабочего HTML содержала отдельный `.container.character-copy`, за которым следовала `.character-stage` вне общего контейнера. Отступы текста складывались с высотой полноширинной картинки; двухколоночная композиция исчезла.
- `.character-stage` имела `width: 100%` относительно всей секции. При ширине 1440 px высота изображения составляла 981 px ещё до текстового блока.
- Глобальные `.container`, `.product-stage`, типографические токены и `h2` не являлись причиной регрессии. Изображение было в обычном потоке; `z-index` не скрывал текст. `overflow: hidden` находился только на figure и не являлся причиной исчезновения бордера.
- Бордер исчез из-за исключения `.final-section` из общего списка разделителей. Ранее применялся `border-top: 1px solid var(--line)`; это подтверждено сохранённым снимком в `background-review.html`.

## Исправление

Ниже описан промежуточный вариант. Текущая раскладка по последующим указаниям Дмитрия: крупный фон слева, текст справа, плавное затемнение границ. На 1440 px сцена 1267 × 863 px, секция 922 px. На 390 px сцена 390 × 487 px, затем текст в той же секции. У всех заголовков после hero общий стиль h3; это изменение отдельно разрешено Дмитрием. Hero не изменён. Актуальный diff: `diamond-character-z-layout.diff`; актуальные статические иллюстрации: `previews/03-character-z-*.png`.

- Текст, CTA и picture объединены в `.container.character-layout`.
- Десктоп: двухколоночная сетка с существующими пропорциями сцен `.82fr / 1.38fr` и существующим диапазоном gutter. Восстановлены прежние параметры финальной секции: минимальная высота 690 px и вертикальные отступы 100 px.
- Ниже 850 px — одна колонка, естественная высота, отступы 64 px; на телефоне — 48 px и межблочный интервал 24 px. Отдельного текстового экрана нет.
- Бордер возвращён локально через `.final-section`, в точности `1px solid var(--line)`, на всю ширину. Figure находится внутри padding контейнера, её псевдоэлемент ограничен её собственными границами.
- Утверждённые изображения сохраняют пропорции и `contain`; объекты не переставлялись и не ретушировались. Копирайт, шрифты, глобальная сетка и остальные разделители не менялись.

## Проверки и ограничения

Сохранён checkpoint рабочих файлов и SHA-256 всех ассетов перед исправлением. Изменения HTML/CSS записаны в `diamond-character-layout-fix.diff`; точный путь checkpoint указан в `diamond-character-validation.json`.

Проверены неизменность всех ассетов, других HTML-секций и CSS-правил, вложенность HTML, уникальные ID, локальные пути, цели ARIA/якорей и синхронизация страницы просмотра. На 1440 px visual в правой колонке имеет расчётный размер около 773 × 527 px; на 390 px — 346 × 432 px. Эти значения получены из CSS, не измерены браузером.

Настоящий браузерный прогон заблокирован: Chrome-коннектор возвращает `Unexpected token '<' ... is not valid JSON`. Скриншоты 1440/390 и измерение `scrollWidth` не выполнены. Ранее сохранённые статические превью показывают предыдущую компоновку; они не выдаются за скриншоты исправления. Для визуального просмотра новой версии используется `diamond-character-review.html` или основной лендинг.

Новых генераций, установки пакетов, массового отката, удаления файлов и деплоя не было.
