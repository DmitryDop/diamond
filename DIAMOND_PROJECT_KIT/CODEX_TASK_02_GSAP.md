# CODEX — задание №2: DIAMOND / движение (НЕ ЗАПУСКАТЬ ДО РЕВЬЮ КАРКАСА)

**Условие запуска:** пользователь уже посмотрел локальную итерацию 1 и явно дал команду на анимации. Брать за основу текущие утверждённые файлы, не редизайнить проект и не менять текст/CTA по своему усмотрению. Сначала перечитать `DIAMOND_MASTER_BRIEF.md`.

1. Подключить через CDN GSAP, ScrollTrigger и SplitText. Без обязательной установки npm. Проверить загрузку библиотек; страница должна быть читабельной и без JS.
2. Hero: появление `DIAM` целиком, `ND` целиком. Бриллиант-«O» — **одним SVG**, отдельное мягкое появление (`opacity`, `y 12–16px`, 0.9–1.2s), плюс микро-параллакс на 10–15px по скроллу. Не применять SplitText к слову DIAMOND. Никаких вращений самого символа.
3. Бита: деликатное дыхание/качание, мягкая инерция от движения курсора, безопасный горизонтальный drag, `touch-action: pan-y` и сохранённая вертикальная прокрутка пальцем. Это PNG, поэтому никаких иллюзий полного 3D-оборота.
4. Для **трёх** названий скролл-сцен («Силуэт», «Фактура», «Свет и тень») — посимвольный reveal через SplitText+ScrollTrigger: opacity 0→1, y 12→0, stagger 0.03–0.05s, один запуск, суммарное впечатление 0.8–1.2s. Не разбивать остальной текст на буквы. Описания — спокойный fade-up, изображения — очень лёгкий reveal/parallax.
5. Не использовать scroll hijacking, бесконечное pinning, тяжёлую blur-анимацию и резкие световые вспышки. Нативная прокрутка важнее эффектности.
6. Учесть `prefers-reduced-motion`, `document.fonts.ready` до SplitText, восстановление текста при reflow/resize, доступность заголовков и fallback при недоступном CDN. Не оставлять блоки невидимыми после JS-ошибки.
7. Проверить desktop/mobile, быстрое пролистывание, смену ориентации, медленный интернет (если есть способ), отсутствие horizontal overflow, кликабельность CTA и консольные ошибки.

**Приёмка:** записать перечень анимаций, их триггеры и длительности, результаты тестов. Не деплоить, не менять PALKAHELP и не делать commit/push без команды пользователя.
